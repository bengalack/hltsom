# 0002 — Static map preview, interactive on click

**Date:** 2026-09-09
**Status:** Accepted
**Supersedes:** [ADR 0001](0001-map-loads-without-click.md), and restores the consent guarantee
in §10 of `docs/superpowers/specs/2026-09-09-hltsom-website-design.md`

## Context

Three positions in sequence:

1. **Original design.** Google Map behind a grey "Vis kart" button. No cookies before consent,
   no banner needed — but the visitor saw an empty box and had to act to learn anything.
2. **[ADR 0001](0001-map-loads-without-click.md).** The owner removed the click. The map loaded
   by itself, deferred by an IntersectionObserver. This solved the usability problem and
   created a compliance one: Google set cookies with no consent, so the site needed a banner.
3. **This decision.** The owner proposed showing a map *image* first, upgrading to the real
   interactive map on click.

The insight in position 3 is that the earlier debate conflated two different things. Seeing
*where the workshop is* is information the visitor should get for free. *Panning, zooming and
getting directions* is interactivity. Only the second needs Google, and therefore only the
second needs consent.

## Decision

The contact block ships a **static map image rendered from OpenStreetMap tiles**, stored at
`assets/img/map-preview.webp` and served from this origin. It sets no cookies, makes no
third-party request, and is visible immediately.

Clicking it replaces the image with Google's interactive embed. That click is the consent
action, so **no cookie banner is required**.

Implementation notes:

- The element is an `<a>` pointing at Google Maps, not a `<button>`. Without JavaScript it
  opens Google Maps in a new tab, so the map is never unreachable. With JavaScript, the click
  is intercepted and the embed is inserted in place.
- The preview was generated by `tests/_mkmap.mjs` (a one-off utility, not part of the site)
  from `tile.openstreetmap.org` at zoom 14. **Regenerate it when the real street address is
  known** — it currently centres on Sandvika generally, because the address is a placeholder.
- **The OpenStreetMap attribution under the map is required by the ODbL licence and must stay
  visible.** Removing it is a licence violation, not a tidy-up.
- Google's own map imagery could not be used for the preview: their terms prohibit caching or
  redistributing it. This is why the preview is OSM and the interactive map is Google.

## Consequences

**The consent problem is gone.** No cookies are set until the visitor asks for the interactive
map. The cookie-consent mechanism listed as a launch blocker under ADR 0001 is no longer
needed, and that open item is withdrawn.

**The usability objection to the original design is also gone** — the visitor now sees the
location without doing anything. This is strictly better than both previous positions rather
than a compromise between them.

**A click is required for interactivity.** This is a deliberate reversal of ADR 0001's
"no click" requirement, made at the owner's own suggestion once the preview made the trade-off
concrete.

**Cost:** a 192KB image in the repository, lazy-loaded so it does not affect first paint, plus
the obligation to regenerate it if the address changes.
